# sparkopy

> CLI tool that reads one table from a Spark Connect server and writes it to one local Parquet file.

## Status

- **Active**
- 2026-10: rewritten in Rust as one static binary. The Python version and its Databricks Connect option were removed.

## Tech Stack

- Language: Rust (version pinned in `rust-toolchain.toml`), one binary crate
- Key dependencies: clap (CLI), tonic and prost (Spark Connect gRPC client), arrow-ipc and parquet
- The Spark Connect protocol code is generated by `build.rs` from the Spark 3.5.1 `.proto` files in `proto/`. protox compiles them, so a build needs no `protoc`.
- Release binaries are static musl builds for linux/amd64 and linux/arm64, linked by cargo-zigbuild with zig (both pinned in `mise.toml`).

## Purpose

Exports one table from a Spark Connect server to a local Parquet file. It streams the Arrow batches that Spark sends straight to the Parquet file and keeps Spark's column types exactly. Only Spark Connect is supported. Databricks Connect is out of scope.

## Key Entry Points

- `src/main.rs`: the command line (`Options`) and `run()`, which returns the exit status (0 success, 1 failed export, 2 usage error)
- `src/export.rs`: `spark_target()` parses the `sc://` URI, and `export_plan()` streams the result to `PATH.tmp` and renames it after success
- `src/tests.rs`: tests against an in-process fake Spark Connect server
- `src/parity_tests.rs`: the parity check against a real server (`just parity`)

## Commands

```bash
# Export one table
sparkopy --spark-uri sc://HOST:15002 --database DB --table TABLE --output PATH

# Development
just setup            # install the pinned tools and arm the git hooks (once per clone)
just fmt              # format the Rust code
just lint             # clippy, actionlint, zizmor, cog
just test             # Rust tests (fake Spark Connect server)
just ci               # full local equivalent of CI
just build            # static linux/amd64 binary at dist/sparkopy
just release-assets   # amd64 and arm64 binaries and SHA256SUMS in dist/release
just parity           # real-server check; needs SPARKOPY_TEST_SPARK_URI
```

A pushed `v*` tag runs `.github/workflows/release.yml`, which attaches `sparkopy-linux-amd64`, `sparkopy-linux-arm64` and `SHA256SUMS` to a GitHub release.

## Relationships

- **Depends on**: a remote Spark Connect server (Spark 3.5)
- **Feeds into**: t_shank, which calls sparkopy with `--spark-uri` to export tables

## Domain Concepts

- **Spark Connect**: the gRPC protocol for clients of a remote Spark server (`sc://HOST[:PORT]` URIs, default port 15002)
- **Arrow batch**: the unit in which Spark Connect sends a result; sparkopy writes each batch to the Parquet file as it arrives
